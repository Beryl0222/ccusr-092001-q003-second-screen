# 城市第二现场客流联动

为大型赛事期间的商圈、文化空间与公共广场等“第二现场”点位提供统一的实时承载口径、导流/暂停建议与内容授权闸门。
`domain.json` 描述点位等级、事件优先级、回执与摄入/系统事件类型。

## 设计要点

服务采用**追加事件日志 + 确定性投影**，不维护可被乱序写坏的可变状态：

- 所有输入（容量快照、入离场计数、计数锚点修正、管制事件、内容授权/撤销、通知回执）都是事件，追加到 JSONL 日志。
- 每次查询/判定都是对“截至某时刻（asOf）已接收事件”的一次**纯折叠**：事件按规范顺序
  （发生时间 → 类型 → 点位 → 设备 → 序号 → 事件ID）归并，因此**乱序、迟到、重复、进程重启重放**都得到同一份稳定状态。
- 投影时刻支持 `?at=` / `X-Now` 注入，可重放任意历史时刻。

针对题面要求的对应实现：

| 要求 | 实现 |
| --- | --- |
| 迟到数据 | 按 `occurredAt` 归并而非到达顺序；接收延迟 >60s 在证据中标注“迟到上报，仍按发生时间纳入” |
| 计数修正 | `count.anchor` 绝对真值锚点；锚点前的计数被显式取代（证据 `used=false`），锚点后按序号累加 |
| 同一设备重复上报 | 双键幂等：同场次同 `eventId`，或同设备同序号同类型（设备重传换 ID 也判重） |
| 跨午夜场次 | 一切以显式 `sessionId` 归并，不同场次互不串扰；计数在同一场次内跨午夜连续 |
| 中心失联恢复 | 状态全部来自日志；进程重启重放 JSONL 即恢复，重复事件再次判重 |
| 设备失联/缺口 | 按设备水位检测缺失序号（`/gaps`），迟到补传后缺口消失，占用为下限估计并在证据中提示 |
| 稳定点位状态 | 确定性折叠，顺序/逆序提交结果 DeepEqual |
| 唯一告警 | 告警为状态机：一个活跃期一条告警，ID 由点位+起点确定性派生；升级沿用、降级不新建、解除关闭、再发才是新告警 |
| 哪次导流造成拥堵 | 对已接受导流比较目标点位指令前后入场速率（>1.5 倍且增量≥20 人/分），窗内新告警建立归因；管制引发的告警不归因 |
| 自动建议可审计 | 建议生成时固化证据快照（每条数据 used/被排除及原因）；运营接受/驳回追加为**不可变** `directive.decision`，`/audit` 可查 |
| 过期授权不得分发 | 分发闸门默认拒绝；必须存在覆盖该时刻、未撤销的授权窗口；管制/疏散/暂停期间一律停止；拒绝落 `enforcement.log` |
| 不暴露观众身份 | 只交换聚合进/出值；摄入侧递归拒绝姓名/证件/手机/人脸/设备指纹/MAC 等字段（`deviceId` 是设备编号） |

建议规则：占用率 ≥90% 或容量满 → 导流（按 协同点位 > 备用点位、空闲座位数排序选择去向）；
管制/紧急疏散，或无可用去向 → 暂停入场。建议带 5 分钟决策 TTL，接受后超过有效期无“已执行”回执则显示“已过期（已接受未执行）”。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/v1/sessions/{sid}/events` | 批量摄入，逐条返回 `accepted/duplicate/rejected` 及原因 |
| GET  | `/v1/sessions/{sid}/summary` | 分区热度、占用、告警、指令（含证据）、归因、缺口、排除项 |
| POST | `/v1/sessions/{sid}/venues/{vid}/propose` | 生成自动建议（导流/暂停入场），返回完整证据 |
| POST | `/v1/sessions/{sid}/directives/{did}/decision` | 运营 `{decision:接受/驳回, operator, reason}`，不可变 |
| POST | `/v1/sessions/{sid}/venues/{vid}/authorize?contentId=` | 内容分发闸门校验，拒绝即落审计 |
| POST | `/v1/sessions/{sid}/events`（`directive.receipt`） | 点位回执：已接收/已执行/已驳回/已过期 |
| GET  | `/v1/sessions/{sid}/audit` | 建议、不可变决策、闸门拒绝记录 |
| GET  | `/v1/sessions/{sid}/gaps` | 各设备水位与缺失序号 |

所有时间点接口支持 `?at=RFC3339`（或 `X-Now`）做历史重放。

## 运行与验收

```bash
go run . -check          # 配置检查
go test ./...            # 13 个引擎用例 + HTTP 端到端（含 -race）
go run . -demo           # 内置乱序场景：跨午夜、迟到、缺口补传、锚点修正、
                         # 重复判重、授权过期、管制、导流归因，输出汇总 JSON 与核对结论
go run . -addr :8000     # 启动服务（事件日志默认 data/events.jsonl）
```

`-demo` 与 `TestOutOfOrderReplayStable` 直接构成验收：同一段乱序事件以顺序与逆序分别提交，
点位状态、告警ID、建议证据 DeepEqual；汇总接口的每条指令都带 `evidence`，逐条说明导流判断使用了哪些有效数据、排除了哪些数据及原因。
